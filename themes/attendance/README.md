# 出勤记录：原初的巫女テルスウラス

`/出勤记录`（`src/features/attendance.cjs`，数据整理在 `src/attendance.cjs`）：最近一次出勤打了哪些谱面、几点到几点，
下面一条近一年的同步日历。跟 `/同步记录` 不一样：没涨分的、被技能强制结束的游玩都算。

作者 2026-10-22 选的：背景科尔《伊甸园》（12 张候选里的 08 号）、画框荷兰国立博物馆 BK-1962-51 胡桃木花卉镶嵌镜框
（F1～F4 里的 F1；候选在 `data/bg-candidates/telseuras/`），来源见 `assets/README.md`。

## 角色

原初的巫女テルスウラス（Telseuras，《紀律》～ As One，落雪曲目 2091，立绘ヒトこもる）。涅菲谢身边的侍女：侍女世家出身，
一辈子在山顶的宫殿里当差，每天把听到的事整理清楚；生日祭上亲手刺伤了涅菲谢，土之力从涅菲谢身上剥落到她身上。
立绘手里拿着一块怀表，跟「出勤」对得上。官方完整立绘 `Telseuras,_Original_Sibyl_Fullbody.png` 475×1080（Miraheze 的 CHUNITHM 剧情维基），
放在 `assets/telseuras-fullbody.png`。

## 版式（横版 2700 宽、最高 1780，JPEG 76、1.5 倍）

- 画框 80 宽：约 1690 年的荷兰胡桃木镜框，四分圆线脚，四角和边上嵌着木片、骨片拼的花（叶子是绿的，对应她的土之力）。
  图的高度会变，框在 `theme.js` 的 `buildFrame` 里按图的大小现拼：原件左右上下对称，素材只裁左上角（L 形，里面那一角是镜子的玻璃，
  `clip-path` 裁掉）、上边一段（胡桃木 + 一格椭圆花饰）、左边一段（胡桃木 + 一格花瓶），别的角和边翻过来用；
  四角和边条同一个缩放比，边条整段整段地排（上下段数取偶数、隔一段左右翻，接缝对称；左右的花瓶要正着、不翻），
  多出来的长度从每段两头的素胡桃木上平均裁掉，花格不会被切成半个。相邻两段多盖 1px，1.5 倍出图时接缝不露底色。
- 框里是油画（垫到框下 4px），原始亮度不调色；内口一圈压暗，像框压在画上。立绘细长，按高度放大到 654×1487，
  放在右边 1912～2566、不透明度 0.62，不压字。
- 左边内容区 1740 宽（132～1872），从上往下：
  - 抬头：「出勤记录」88px，下面一行这场的日期、星期、几点到几点（不是今年的带年份）。
  - 五格统计：时长（首末两次的间隔 + 一首 3 分钟）、游玩次数、谱面张数、新纪录、强制结束。小字和数字整块上下居中、行高压到 1
    （作者嫌小字顶着上边：Segoe Script 的行框上面空得多，按 1.3 排时数字偏下、小字贴着上边）。
  - 最近一次出勤：同一张谱面合成一行，按这场第一次打它的先后排。一行是难度、曲名（放不下先缩到八成五，再省略）、
    这场的最高分、评级、通关标记（几次里最好的）、「新纪录」淡紫小牌。
    - 12 张以内排一栏（`.wide`）：多写定数和这张谱面每一次的分数（`1,006,309 · ✕ · 1,008,797`，✕ 是被强制结束的那次，
      最多写 6 个）；行高按张数把列表那块（742 高）填满，最高 118，字跟着放大，最多 1.3 倍。
    - 13 张以上分两栏、先排满左栏：只写 ×次数（只打一次不写），字不放大（两栏时曲名本来就挤），最多 2 × 12 = 24 张。
      最近这场占满了 Recent 50 时注明前面可能还有（注明占 44 高，列表相应变矮）。
    - 写不下时先留什么（作者 2026-10-22 问的）：
      - 超过 24 张：出了新纪录的全留（抬头那格数了几张，列表里就得看得到），剩下的位置给后打的，画出来还按先后排，
        注明「另有 N 张谱面没画」（`src/attendance.cjs` 的 `pickRows`）。
      - 一行之内：难度、定数、最高分、评级、通关标记、新纪录一定画；曲名至少留 12 个字宽（再长先缩到八成五、再省略）；
        每一次的分数最后让，写不下从后往前少写，最后一个都不写、退回 ×次数（`theme.js` 的 `TITLE_ROOM`）。
      - 通关标记那一格按最宽的一行留，有一张出了新纪录、别的行也空出那一格：分数、评级上下对齐。
    - **不留空**（作者 2026-10-22 嫌第一版列表和日历中间空出一大段）：6 张以下行高到顶也填不满时，整张图变矮
      （1 张约 1156、3 张约 1392），立绘跟着缩小；7 张以上都是 1780 左右。图高取双数，1.5 倍出图正好是整像素
      （单数时最底下一行只盖住半个像素，露一条暗线）。
  - 近一年：紧接在列表下面，53 周 × 7 天，周一在上，月份标在 1 号那一周，今天描一圈边，今天以后不画。
    颜色是四档绿（1～9、10～19、20～39、40 条以上），标题右边写「按同步那天 · N 天有同步」。
- 颜色照她的衣服：披肩和裙子的苔绿、围裙的象牙白（标题带）、发梢的淡紫（新纪录、标题带下面的双线）、刺绣的旧金。
  难度、通关标记的颜色跟 `/同步记录`、`/b50` 一样。

## 数据的坑（2026-10-22 拿作者的真数据核过）

- heatmap 一天的数是那天同步上去的游玩条数，按同步那天记：10/16 打的两场（3 + 17 首）第二天才同步，heatmap 记在 10/17（20 条）。
  日历照实画，不拿 Recent 50 去改。
- 同一场里相邻两首差 1～5 分钟，两场之间差好几个小时；按「隔了 2 小时以上」切场（排卡排上一个多小时也算同一场）。
- 最好成绩上的 `play_time` 是最后一次打这张谱的时间，不是打出这个分数的时间；`upload_time` 只在成绩变好时才变。
  所以新纪录 = 现在的最好成绩等于这场最高分，而且跟那次游玩是同一次同步传的（相差 15 秒以内）。

## 工具（`design/` 不进仓库）

- `node themes/attendance/design/render-real.cjs`：用本机真数据出草图（Recent 50 走开发者接口，heatmap 和全部成绩用 `.env` 的个人密钥），
  图存 `data/try/attendance-draft.jpg`，数据存 `data/try/attendance-real.json`。
- `node themes/attendance/design/make-example.cjs`：重新生成 `examples/preview-data.json`（编的一场、编的一年）。
- `node themes/attendance/design/render-sizes.cjs`：1、3、7、9、12、13、20、24 张几种情况各出一张（0.5 倍），看排法和图的高度；
  `07-crowded` 是长曲名 + 同一张打了 6、8 次，看每一次的分数让不让曲名。
- `python themes/attendance/design/prepare-materials.py`：油画原图缩到 4000 宽；画框原图裁三块（坐标和余量写在脚本里）。
- `node themes/attendance/design/perf.cjs`：按正式参数出两遍、打印计时。配 `data/scratch/song-speed/one-core.ps1` 钉在一个核上、
  不用显卡，模拟服务器（2026-10-22：单核 2.3 秒，服务器约 8 秒）。
- `npm run preview -- attendance`：用示例数据出图。
